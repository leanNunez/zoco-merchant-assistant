# Seguridad: amenazas, controles y riesgos que quedan

Las tres condiciones críticas de la consigna son: acceso entre empresas, herramienta o escritura
no autorizada, y escritura duplicada al reintentar. Cada una tiene un control estructural (lo
decide el código, no el modelo ni el texto del usuario) y al menos un test que falla si se rompe.

| Condición crítica | Control estructural | Prueba |
|---|---|---|
| Acceso entre empresas | La empresa viene del contexto autenticado, nunca del texto ni de los argumentos. Los reclamos de cada empresa viven en su propio archivo (`src/cortex/tools/adapters/claims.py`) y cortex.db filtra cada consulta por empresa | `tests/cortex/integration/test_tenancy.py::test_every_query_on_company_data_filters_by_company`, `tests/cortex/integration/test_kit_scenarios.py::test_t05_naming_another_company_ends_the_run_with_a_refusal`, `tests/cortex/integration/test_tenancy.py::test_t06_interleaved_conversations_of_two_companies_stay_separated`, `tests/cortex/integration/test_docs.py::test_a_company_without_documents_gets_nothing_never_somebody_elses`, `tests/cortex/integration/test_chat.py::test_an_event_for_another_company_is_refused` |
| Herramienta o escritura no autorizada | Cadena que deniega por defecto y confirmación exacta de los valores | `tests/cortex/unit/test_policy.py::test_naming_a_company_or_a_role_is_a_scope_violation_that_ends_the_run`, `tests/cortex/integration/test_kit_scenarios.py::test_t05_naming_another_company_ends_the_run_with_a_refusal` (el adaptador no se llama), `tests/cortex/integration/test_kit_scenarios.py::test_t03_an_unknown_tool_is_rejected_without_any_external_call`, `tests/cortex/unit/test_policy.py::test_a_principal_without_the_permission_is_denied`, `tests/cortex/integration/test_writes.py::test_without_a_confirmation_nothing_is_written_and_the_user_is_asked` |
| Escritura duplicada al reintentar | Registro por (empresa, `operation_id`) y conciliación antes de reintentar | `tests/cortex/integration/test_writes.py::test_concurrent_executions_of_one_command_have_one_effect`, `tests/cortex/integration/test_writes.py::test_t09_the_same_operation_id_twice_files_one_claim`, `tests/cortex/integration/test_writes.py::test_the_same_command_after_a_restart_still_files_one_claim`, `tests/cortex/integration/test_writes.py::test_a_write_committed_before_a_timeout_is_reconciled_not_repeated`, `tests/cortex/integration/test_chat.py::test_three_separate_processes_file_one_claim` |

## Lo que se decidió no agregar, y por qué

| No se agregó | Motivo |
|---|---|
| Firmas de eventos, login, JWT, límite de tasa, API HTTP | Piden un servidor o claves que la consigna no exige |
| Filtros de inyección por palabras o semánticos; filtro de salida | No se pueden probar con un modelo guionado y dan falsos positivos. Una respuesta no puede llevar datos de otra empresa porque el modelo solo ve una |
| Cifrado en reposo y borrado por retención | Piden dependencias y un planificador que la consigna no exige |
| Mover la lista de campos de alcance o las políticas a configuración | Un archivo podría aflojarlas; hoy están en código y la configuración solo puede confirmarlas |
| Clave de trazas aleatoria por proceso | Rompe la reproducibilidad de las trazas y de los resultados |

## Riesgos que quedan

| Riesgo | Por qué queda | Qué lo cerraría |
|---|---|---|
| Los eventos de chat no van firmados; cualquier principal de la empresa puede tomar una conversación | La consigna no da servidor ni claves | Firma del evento y rol de operador |
| Un solo proceso y SQLite local; el candado de una ejecución por conversación no vence nunca y el arranque libera todos | No se probó con varios servidores | Candados con vencimiento en una base compartida |
| Los mensajes se guardan completos, sin retención ni borrado | Son la memoria de la conversación | Política de retención y un planificador |
| La clave del seudónimo de las trazas es pública en la demostración | Hace reproducibles las trazas | `CORTEX_TRACE_KEY` propia (ya soportada) |
| Repetir un `run_id` después de una toma de control rechazada devuelve el resultado guardado, sin los eventos de la denegación | Esos eventos se agregan a la traza después de guardar el resultado | Guardarlos antes de cerrar la ejecución |
| La base guarda completos los valores de las acciones pendientes y de los compromisos; solo las vistas (traza, ficha del operador, salida) los enmascaran | Hacen falta para ejecutar la escritura confirmada y para que la persona retome | Cifrado en reposo y política de retención |
| El verificador independiente no ve lo que no se guarda: `external_calls_to_rejected_tool` | Se cuenta en el borde de la herramienta | Que el sistema externo registre sus llamadas |
| No hay corrida con un LLM real | IT no dio acceso | Enchufar el modelo en `src/cortex/runner/model.py` |
| El job `security` de CI es informativo (`continue-on-error`) | Un hallazgo nuevo no debe bloquear la entrega | Volverlo obligatorio |

## Cómo verificarlo

```bash
make check   # lint, tipos estrictos, contratos de arquitectura y tests (dos zonas horarias)
make eval    # los escenarios del kit y las variantes, comparados con los archivos SQLite
uv run pytest tests/cortex/integration/test_tenancy.py -q
uv run pytest tests/cortex/unit/test_policy.py -q
uv run pytest tests/cortex/integration/test_writes.py tests/cortex/integration/test_chat.py -q
uv run pytest tests/cortex/unit/test_redaction.py tests/cortex/integration/test_traces.py -q
```

`tests/unit/test_docs_consistency.py` comprueba que cada ruta y cada test citados arriba existen.
